# Two-Tab Layout Design

## Goal
把当前单页+左侧抽屉的 Flutter 客户端，调整为底部两页式结构：首页用于临时测试和悬浮球控制；设置页用于后端地址、转写参数和调试入口等配置。

## Information Architecture
- 首页
  - 顶部状态摘要：后端配置状态、悬浮球状态
  - 测试输入区：用于验证填入当前输入框
  - 测试操作区：悬浮球开关、录音/实时转写/转写结果
- 设置页
  - 连接：后端 Base URL、API Key、扫码填充
  - 转写：LLM 处理、无文本断开秒数
  - 悬浮球：平台说明与状态
  - 调试：debug 模式下展示 Talker 日志入口

## Visual Direction
- 参考 DESIGN.md 的 warm neutral 极简风格
- 去掉抽屉与厚重分隔，使用暖白背景、轻边框、低对比卡片分组
- 底部导航保持克制，只放“首页 / 设置”两项
- 首页优先展示操作，不做复杂装饰
- 设置页采用分组列表样式，接近 Happy 项目那种清爽设置页体验

## Interaction
- 首页底部导航切换，无侧滑抽屉
- 悬浮球开关直接在首页可见，减少测试路径
- 设置项尽量内联编辑，避免多层弹窗；扫码仍可通过单独页面进入
- debug 日志入口只在 kDebugMode 可见

## Scope
- 调整主页面结构与样式
- 重构设置入口与配置编辑方式
- 保留现有转写、实时转写、悬浮球逻辑
- 不改后端协议与核心转写能力
